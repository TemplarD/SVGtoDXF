# План автотестирования SVG to DXF Converter

## Обзор
Автотестирование предназначено для проверки всех аспектов работы приложения как для пользователя (через F12), так и для ИИ (программно).

**🆕 МОДУЛЬНАЯ СИСТЕМА**: Реализован модульный автотест с фокусом на проблеме диалоговых окон.

## Архитектура тестирования

### Два режима активации:
1. **Пользовательский:** F12 → кнопка "Создать отчет"
2. **ИИ режим:** программная активация → автоматическое сохранение логов

### 🆕 Модульная структура:
- **AutotestRunner** - основной класс запуска
- **7 тестовых модулей** - независимое тестирование
- **Критические тесты** - фокус на проблемах диалогов

### Локации логов:
- **Пользователь:** `~/svg-to-dxf-converter/logs/`
- **ИИ:** `./autotest_logs/`
- **🆕 Внутрипрограммный дебаг:** специальная панель в UI по F12

### 🆕 Система внутрипрограммного дебага:
- **Проверка Tauri API:** доступность window.__TAURI__, core, invoke
- **Детальное логирование:** каждый вызов функции с параметрами
- **Визуализация файловой системы:** количество папок/файлов/SVG
- **Отслеживание ошибок:** полный стек и типы ошибок
- **Мониторинг UI:** состояние элементов и навигации
- **Интеграция с автотестами:** автоматическая проверка дебаг логов

## 🆕 Модульные тестовые сценарии

### 1. Dialog Module (ФОКУС НА ПРОБЛЕМЕ)
- **Проверка функций диалогов:** customDialog, customFolderDialog
- **Интеграция с Tauri API:** get_home_directory, list_directory
- **Инициализация домашней директории:** реальная загрузка файлов
- **Содержимое диалогов:** наличие файлов и папок
- **Критические тесты:** runDialogCriticalTests()
- **🆕 Внутрипрограммный дебаг:** детальные логи Tauri API вызовов
- **🆕 Отладка файловой системы:** проверка доступности invoke функций
- **🆕 Логирование ошибок:** полный стек вызовов и типы ошибок

### 2. UI Module
- **Проверка кнопок:** selectFilesBtn, selectFolderBtn, convertBtn, clearBtn, helpBtn
- **Элементы статуса:** статус бар, прогресс бар
- **Контейнеры:** основной контейнер, список файлов

### 3. FileSystem Module
- **Tauri API:** доступность invoke функций
- **Системная информация:** ОС, архитектура
- **Операции с директориями:** get_home_directory, get_system_roots

### 4. Conversion Module
- **Команды конвертации:** convert_single_file, convert_multiple_files
- **Процесс конвертации:** тестовые SVG файлы
- **Обработка ошибок:** несуществующие файлы

### 5. Performance Module
- **Время загрузки UI:** замер производительности
- **Скорость открытия диалогов:** время отображения
- **Файловая система:** производительность list_directory
- **Использование памяти:** JavaScript heap size

### 6. Accessibility Module
- **Навигация клавиатурой:** tabIndex для кнопок
- **Контрастность цветов:** стили элементов
- **Размеры элементов:** доступность взаимодействия
- **Подсказки:** tooltips

### 7. Logging Module
- **Функции логирования:** debugLog доступность
- **Директория логов:** get_log_directory

## 🚨 Фокус на проблеме диалогов

### Проблема: В диалогах не отображаются файлы
**Причина:** Начальный путь "/" недоступен, нужно использовать домашнюю директорию

### Решение:
1. **Добавлена команда** `get_home_directory` в Rust
2. **Изменена инициализация** диалогов на асинхронную
3. **Исправлены поля** структуры FileItem (is_directory)
4. **Улучшена навигация** с защитой от выхода выше домашней директории

### Тестирование решения:
- ✅ Проверка получения домашней директории
- ✅ Реальное открытие диалога
- ✅ Загрузка содержимого файловой системы
- ✅ Проверка наличия файлов и папок
- ✅ Корректность отображения пути
